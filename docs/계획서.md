# 설문 집계기 구현 계획서

근거: `docs/설계서.md` (승인됨 2026-11-17)

## 1. 파일 구성
| 파일 | 역할 |
|---|---|
| `index.html` | 결과물. 화면과 계산 로직이 모두 들어 있는 HTML 파일 하나 |
| `tests/tally.test.mjs` | 계산 로직 자동 시험. Node.js 기본 시험 도구(`node --test`)만 쓰고 설치할 것이 없음 |
| `.nojekyll` | GitHub Pages가 파일을 가공하지 않고 그대로 내보내게 하는 빈 파일 |

## 2. 계산 로직을 화면과 떼는 방법
- `index.html` 안에서 계산 로직을 `<script id="tally-core">` 블록 하나에만 둔다. 이 블록은 화면(문서 요소)을 건드리지 않는다.
- 화면 코드는 별도 `<script>` 블록에 두고, 계산 로직의 결과를 받아 표로 그리기만 한다.
- 자동 시험은 `index.html`에서 `tally-core` 블록만 꺼내 Node.js에서 실행한다. 그래서 파일은 하나로 유지되고, 시험하는 코드와 실제 쓰는 코드가 같다.

## 3. 처리 세부 (설계서를 코드로 옮길 때 정한 점)
- 줄은 줄바꿈으로, 칸은 탭으로 나눈다(설계서 5장 가).
- 공백만 있는 줄은 빈 줄로 보고 무시한다(5장 나). 칸이 탭뿐인 줄도 여기에 들어간다.
- 빈 줄이 아닌 첫 줄을 머리글로 본다.
- 안내 문구의 "몇 번째 줄"은 붙여넣은 글의 줄 번호다(머리글 줄이 1번째).
- 평균은 정수 계산으로 반올림한다(합계×100÷유효 수를 반올림). 그래서 2.675처럼 컴퓨터 소수 오차로 잘못 내림되는 경우가 없다.
- 붙여넣은 내용이 바뀔 때마다 바로 다시 집계한다(집계 버튼 없음).
- 페이지에 외부 요청을 막는 보안 정책(Content-Security-Policy)을 넣어, 실수로 외부 요청 코드가 들어가도 브라우저가 막게 한다.

## 4. 작업 순서
각 단계가 끝날 때마다 커밋한다.

1. 계획서 작성 → 확인: 이 문서
2. `.nojekyll` 추가 → 확인: 저장소 맨 위에 크기 0인 파일
3. 자동 시험 작성 → 확인: 설계서 사례1~4, 칸 수 불일치, 합계 검사, 반올림 사례가 들어 있음
4. 계산 로직 작성 → 확인: `node --test tests/tally.test.mjs` 모두 통과
5. 화면 작성 → 확인: 브라우저에서 설계서 6.2, 6.4, 6.5 기준을 하나씩 확인
6. PR 생성

## 5. 시험 실행 방법
```bash
node --test tests/tally.test.mjs
```
